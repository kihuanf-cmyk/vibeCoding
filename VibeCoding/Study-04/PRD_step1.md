# PRD Step 1: 냉장고 이미지에서 재료 인식

<!-- Created: 2026-09-11 19:47:57 +09:00 -->

## 1. 개요

사용자가 냉장고 사진을 업로드하면 서버가 OpenRouter의 `inclusionai/ling-3.0-flash-vl:free` 모델을 호출해 사진 속 식재료를 식별한다. 결과는 사람이 확인하고 수정할 수 있는 구조화된 재료 목록으로 제공한다.

## 2. 목표

- 냉장고 사진을 파일 업로드 또는 모바일 카메라로 입력받는다.
- 사진에서 식재료의 이름, 수량 추정, 상태, 신뢰도를 추출한다.
- 인식 결과를 사용자가 검토하고 수정할 수 있게 한다.
- OpenRouter API 키가 클라이언트에 노출되지 않게 한다.

### 범위 제외

- 유통기한의 정확한 판독 및 식품 안전 판정
- 영양 성분 계산
- 여러 사진의 자동 병합
- 사용자별 영구 저장, 이는 Step 3에서 구현한다.

## 3. 주요 사용자 흐름

1. 사용자가 냉장고 사진을 선택하거나 촬영한다.
2. 앱이 파일 형식과 크기를 검증하고 미리보기를 보여준다.
3. 사용자가 `재료 인식`을 실행한다.
4. 서버가 이미지를 모델에 전달한다.
5. 앱이 로딩 상태와 실패 시 재시도 버튼을 표시한다.
6. 인식된 재료 목록을 보여주고 사용자가 이름, 수량, 상태를 수정한다.
7. 사용자가 결과를 확정하면 Step 2의 레시피 추천으로 이동한다.

## 4. 기능 요구사항

- 지원 형식: JPEG, PNG, WebP
- 최대 파일 크기: 10MB
- 이미지가 없거나 손상된 경우 요청을 전송하지 않는다.
- 서버는 이미지 MIME 타입과 실제 파일 내용을 모두 검증한다.
- 모델 응답은 JSON 스키마로 파싱하고, 파싱 실패 시 사용자에게 재시도를 안내한다.
- 식재료가 없으면 빈 목록과 개선된 촬영 안내를 반환한다.
- 모델이 확신하지 못한 항목은 `confidence`를 낮게 표시한다.
- 사용자는 인식 결과를 추가, 삭제, 이름 변경할 수 있다.

## 5. 결과 데이터 계약

```json
{
  "items": [
    {
      "name": "달걀",
      "quantity": "6개",
      "condition": "신선해 보임",
      "confidence": 0.94
    }
  ],
  "notes": "냉장고 하단 선반은 일부 가려져 있습니다."
}
```

`confidence`는 0 이상 1 이하이며, 서버가 범위를 벗어난 값은 보정한다. 모델이 반환한 임의의 필드는 클라이언트에 그대로 전달하지 않는다.

## 6. API 설계

### `POST /api/ingredients/recognize`

- 요청: `multipart/form-data`, 필드명 `image`
- 서버 동작: 이미지 검증 후 OpenRouter Chat Completions API 호출
- 모델: `inclusionai/ling-3.0-flash-vl:free`
- 성공: `200 OK`, 위 결과 데이터 계약 반환
- 잘못된 파일: `400 Bad Request`
- 모델 일시 오류: `502 Bad Gateway` 또는 재시도 가능한 `503 Service Unavailable`
- 호출 제한 초과: `429 Too Many Requests`

서버 프롬프트는 “사진에 실제로 보이는 식재료만 추출하고, 추측한 품목은 별도로 표시하며, 지정 JSON 형식만 반환하라”는 규칙을 포함한다.

## 7. 화면 요구사항

- 업로드 영역: 파일 선택, 카메라 촬영, 선택한 이미지 제거
- 결과 영역: 재료명, 수량, 상태, 신뢰도, 편집 컨트롤
- 상태: 초기, 업로드 중, 인식 중, 성공, 실패, 빈 결과
- 모바일 화면에서 업로드와 결과 편집이 세로 흐름으로 사용 가능해야 한다.

## 8. 보안 및 개인정보

- `OPENROUTER_API_KEY`는 서버 환경 변수로만 사용한다.
- 원본 이미지는 기본적으로 저장하지 않으며 요청 처리 후 폐기한다.
- 로그에 이미지, API 키, 전체 모델 응답을 기록하지 않는다.
- 업로드 파일명은 경로로 사용하지 않고 서버가 생성한 식별자를 사용한다.

## 9. 수용 기준

- 정상적인 냉장고 사진으로 재료 목록이 반환된다.
- 지원하지 않는 파일과 10MB 초과 파일이 차단된다.
- 모델 오류와 빈 결과가 구분되어 표시된다.
- 사용자가 결과를 수정한 뒤 Step 2로 전달할 수 있다.
- 브라우저 개발자 도구에서 OpenRouter 키가 발견되지 않는다.

## 10. 다음 단계 의존성

Step 2는 이 문서의 `items` 결과를 입력으로 받아 레시피를 생성한다. 사용자가 수정한 최종 목록을 모델 입력으로 사용해야 하며, 원본 이미지 자체를 Step 2에 다시 보내는 것은 기본 동작으로 하지 않는다.
