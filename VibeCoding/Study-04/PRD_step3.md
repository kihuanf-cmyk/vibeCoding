# PRD Step 3: 사용자 프로필과 레시피 저장

<!-- Created: 2026-09-11 19:47:57 +09:00 -->

## 1. 개요

사용자가 프로필을 만들고 식단 선호, 알레르기 및 제외 재료를 관리하며, Step 2에서 생성한 레시피를 저장하고 다시 확인할 수 있게 한다.

## 2. 목표

- 최소한의 정보로 사용자 프로필을 생성한다.
- 개인 선호를 다음 레시피 추천에 자동 반영한다.
- 레시피를 저장, 조회, 검색, 삭제할 수 있게 한다.
- 저장 데이터의 사용자 소유권과 삭제를 보장한다.

### 범위 제외

- 소셜 로그인 제공자 연동
- 여러 사용자의 공유 주방
- 장보기 결제 및 배송
- 냉장고 재고의 영구 자동 추적

## 3. 프로필 정보

```json
{
  "displayName": "민수",
  "servingsDefault": 2,
  "diet": "none",
  "allergies": ["땅콩"],
  "avoidIngredients": ["고수"],
  "defaultMaxMinutes": 30
}
```

- `displayName`: 1~40자
- `servingsDefault`: 1~12
- `diet`: 허용된 선택지 중 하나
- 알레르기와 제외 재료: 각각 최대 30개
- 민감한 건강 정보는 필수로 받지 않으며, 입력하지 않아도 앱을 사용할 수 있어야 한다.

## 4. 주요 사용자 흐름

1. 사용자가 처음 방문하면 프로필 생성 화면을 본다.
2. 이름과 선택적인 선호 정보를 입력하고 저장한다.
3. 프로필의 알레르기 및 제외 재료를 수정한다.
4. Step 2에서 생성한 레시피 상세 화면의 `저장`을 누른다.
5. 저장 목록에서 레시피를 검색하고 상세를 다시 연다.
6. 사용자가 레시피 또는 프로필을 삭제할 수 있다.

인증 기능이 아직 없는 MVP에서는 서버가 발급한 익명 사용자 ID를 HttpOnly 쿠키로 유지한다. 정식 출시 전에는 이메일, OAuth 등 계정 인증을 도입하고 기존 익명 데이터를 계정으로 이전할 수 있어야 한다.

## 5. 기능 요구사항

- 프로필 생성, 조회, 수정
- 프로필 기본값을 Step 2의 레시피 추천 폼에 자동 반영
- 레시피 저장 시 중복 저장을 방지한다.
- 저장 레시피의 제목, 요약, 재료, 조리 단계, 생성 시점, 원본 재료 목록을 보존한다.
- 저장 목록을 최신순, 제목순으로 정렬한다.
- 제목과 재료명으로 저장 레시피를 검색한다.
- 레시피 단건 삭제와 전체 데이터 삭제를 제공한다.
- 삭제 작업은 확인 절차를 거치며 복구되지 않음을 알린다.

## 6. 데이터 모델

### `UserProfile`

```text
id                string, primary key
displayName       string
servingsDefault   integer
diet              string
allergies         string[]
avoidIngredients  string[]
defaultMaxMinutes integer
createdAt         datetime
updatedAt         datetime
```

### `SavedRecipe`

```text
id                string, primary key
userId            string, indexed
recipe            validated JSON object from Step 2
sourceIngredients JSON array
createdAt         datetime
updatedAt         datetime
```

`userId`에 대한 서버 측 권한 검사를 모든 조회, 수정, 삭제 요청에서 수행한다. 클라이언트가 전달한 `userId`를 신뢰하지 않는다.

## 7. API 설계

### 프로필

- `POST /api/profile`: 프로필 생성
- `GET /api/profile`: 현재 사용자 프로필 조회
- `PATCH /api/profile`: 허용된 프로필 필드 수정
- `DELETE /api/profile`: 프로필 및 연결 데이터 삭제

### 저장 레시피

- `POST /api/recipes/saved`: Step 2 결과 검증 후 저장
- `GET /api/recipes/saved`: 현재 사용자 저장 목록 조회
- `GET /api/recipes/saved/:id`: 저장 레시피 상세 조회
- `DELETE /api/recipes/saved/:id`: 현재 사용자 레시피 삭제

성공 응답은 JSON으로 반환하고, 인증되지 않은 요청은 `401`, 다른 사용자의 리소스 접근은 존재 여부를 추론할 수 없도록 `404`로 처리한다.

## 8. 화면 요구사항

- 프로필 설정: 이름, 인분, 식단, 알레르기, 제외 재료, 기본 조리 시간
- 저장 레시피: 검색 입력, 정렬 선택, 목록, 빈 상태
- 레시피 상세: 저장 시점, 사용 재료, 레시피 본문, 삭제 버튼
- 오류 상태: 저장 실패, 세션 만료, 삭제 실패
- 모바일에서 프로필 입력과 저장 목록을 스크롤 가능한 단일 흐름으로 제공한다.

## 9. 보안 및 개인정보

- 세션 쿠키는 `HttpOnly`, `Secure`, 적절한 `SameSite` 속성을 사용한다.
- 프로필과 레시피는 사용자별로 분리한다.
- API 키와 모델 호출 정보는 저장 레시피나 클라이언트 응답에 포함하지 않는다.
- 알레르기 정보는 민감할 수 있으므로 로그와 분석 이벤트에서 제외한다.
- 전체 삭제 요청은 프로필, 저장 레시피, 세션 연결 데이터를 함께 삭제한다.
- 레시피 본문을 저장하기 전 서버 스키마 검증과 최대 길이 제한을 적용한다.

## 10. 수용 기준

- 사용자가 프로필을 만들고 새로고침 후에도 설정을 확인할 수 있다.
- 프로필의 알레르기와 제외 재료가 Step 2 기본 조건에 반영된다.
- 유효한 Step 2 레시피를 저장하고 목록에서 다시 열 수 있다.
- 같은 레시피를 반복 저장해도 중복 항목이 생기지 않는다.
- 사용자는 자신의 레시피만 조회하고 삭제할 수 있다.
- 단건 삭제와 전체 데이터 삭제가 실제 저장소에서 반영된다.
- 키, 세션 비밀 값, 다른 사용자의 데이터가 브라우저 응답과 로그에 노출되지 않는다.

## 11. 단계별 출시 계획

1. MVP: 익명 사용자 ID, 프로필 CRUD, 레시피 저장 및 삭제
2. 계정화: 이메일 또는 OAuth 로그인, 익명 데이터 이전
3. 확장: 즐겨찾기 태그, 최근 사용 재료, 장보기 목록 연동
